## Introduction

Puth is a browser testing tool focused on stability, performance, and rich feedback. The docs are client-agnostic: the API is the same whether you use PHP, JavaScript, Java, or Go.

**Security note:** Puth is meant for local dev and CI. Do not expose it publicly.

## What is Puth?

Puth is a browser testing framework built on top of Puppeteer. It is a client/server system: you run a Puth server that drives the browser, then connect a client SDK to it.

## 1) Run the Puth server

Run Puth locally using Docker or npm.

### Npm package

You can install Puth globally or inside your project. The package is small, but Chrome is not. Puth checks for a compatible Chrome in:

- `~/.cache/puth`
- `$(pwd)/.cache/puppeteer`

If none is found, it will download Chrome and ask where to store it. Using the home directory avoids multiple copies.

`npm install --global puth` then `puth start`

### Docker/Podman

The OCI image ships with Chrome pre-installed.

`docker run -it --rm -p 127.0.0.1:7345:7345 puthio/puth:0.7.1`

### Docker Compose

```yaml
services:
  puth:
    image: puthio/puth:0.7.1
    ports:
      - 127.0.0.1:7345:7345
    # Mount a folder for snapshots if you want to export them as artifacts
    # volumes:
    #   - ./puth/snapshots:/puth/storage/snapshots
```

## 2) Point your client at Puth

Configure your client to use the Puth server URL, usually:

`http://127.0.0.1:7345`

## GUI

The Puth GUI is built into the server. Open the server URL in a browser to view it.

## Clients and integrations

Currently, the only framework integration is Laravel. The core client SDKs are language-agnostic.

## 4) Run tests in CI

Start the Puth server in your CI job and run your client tests as usual. Keep Puth on a private network only.
